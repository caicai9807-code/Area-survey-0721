# 计划外普查站点明细增加“普查原因” — 功能规格说明书

> 版本：V1.0
> 日期：2026-07-22
> 状态：方案已通过，已实施，交互验收通过
> 适用页面：`plan-outside-survey-site-details.html`

## 一、功能定义

在“计划外普查站点明细”页面增加“普查原因”筛选项和列表字段，使计划经营部能够查看、筛选每个站点最新计划外普查任务的发起原因。

## 二、本期范围

- 筛选区新增“普查原因”下拉框。
- 下拉选项为：全部、面积变化、一管到户、新开户及增容、趸售用户。
- 筛选项放在“普查状态”之后。
- 列表新增“普查原因”列。
- 列表字段取该站点最新任务的普查原因。
- 普查原因与现有筛选条件采用AND关系。
- 同步更新详情跳转携带的最新任务数据口径和项目文档。

## 三、不在本期范围

- 不新增或修改普查原因枚举。
- 不支持多选原因。
- 不按历史任务原因筛选。
- 不调整站点去重、同步、退回和详情业务规则。

## 四、字段规则

| 场景 | 字段 | 控件/格式 | 规则 |
|------|------|-----------|------|
| 筛选区 | 普查原因 | 下拉单选 | 默认“全部”，精确匹配 |
| 列表 | 普查原因 | 文本 | 展示最新任务的普查原因 |

### 4.1 枚举

| 选项 | 说明 |
|------|------|
| 全部 | 不限制普查原因 |
| 面积变化 | 因面积变化发起的计划外普查 |
| 一管到户 | 因一管到户业务发起 |
| 新开户及增容 | 因新开户或增容发起 |
| 趸售用户 | 因趸售用户业务发起 |

## 五、最新任务口径

页面继续先按站点唯一键去重并选择最新任务完整快照，再按普查原因筛选。若同一站点的历史任务原因是“面积变化”、最新任务原因是“一管到户”，则：

- 列表展示“一管到户”。
- 筛选“一管到户”时命中。
- 筛选“面积变化”时不命中。

## 六、用户故事

### US-01 查看普查原因

```gherkin
场景: 查看站点最新任务原因
  假如 某站点最新计划外普查任务的原因是“一管到户”
  当 用户查看计划外普查站点明细
  那么 该站点“普查原因”列显示“一管到户”
```

### US-02 按普查原因筛选

```gherkin
场景: 筛选面积变化任务站点
  当 用户选择普查原因“面积变化”并点击查询
  那么 列表仅展示最新任务原因为“面积变化”的站点

场景: 与其他条件组合筛选
  当 用户选择普查状态“已完成”和普查原因“面积变化”
  那么 列表仅展示同时满足两个条件的最新站点记录
```

### US-03 重置

```gherkin
场景: 重置筛选条件
  当 用户点击重置
  那么 普查原因恢复为“全部”
  并且 其他筛选项按现有规则恢复
```

## 七、业务流程

```mermaid

  A[全部计划外任务站点] --> B[按站点去重选最新任务]
  B --> C[读取最新任务普查原因]

  D --> E[分页]
  E --> F[列表展示普查原因]
```

## 八、交互与布局

- “普查原因”放在“普查状态”之后。
- 筛选区继续采用四列、标签与控件同行的统一布局，后续字段自动顺延。
- 列表“普查原因”列建议放在“普查状态”之后、“下发状态”之前。
- 新增列后保持表格内部横向滚动，操作列继续固定右侧。
- 无合法原因值时显示“—”，但现有模拟数据应全部使用合法枚举。

## 九、异常与边界

- 未知原因值不得导致页面报错，列表显示“—”，且不命中四个具体选项。
- 查询无结果时沿用现有空状态。
- URL查询参数建议使用 `reason`，详情返回时继续恢复该筛选条件。

## 十、验收标准

- [ ] 筛选区正确展示普查原因下拉。
- [ ] 下拉选项、顺序和默认值正确。
- [ ] 列表新增普查原因列且值来自最新任务。
- [ ] 单独筛选、组合筛选和重置正确。
- [ ] 同站点历史任务原因不参与匹配。
- [ ] 详情返回后恢复普查原因筛选。
- [ ] 表头、数据行和空状态列数一致。
- [ ] 横向滚动和右侧操作列不受影响。

## 十一、已确认事项

- 筛选区和列表都新增“普查原因”。
- 枚举为面积变化、一管到户、新开户及增容、趸售用户。
- 筛选项放在普查状态之后。
- 只使用最新任务的普查原因，不回查历史任务。
